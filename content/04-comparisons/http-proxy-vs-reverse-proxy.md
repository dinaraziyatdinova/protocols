# HTTP Proxy vs Reverse Proxy

**Вопрос:** Посредник на стороне клиента и сервера.

| Критерий | HTTP Proxy | Reverse Proxy |
|---|---|---|
| Роль | Посредник, который отправляет запросы от имени клиента. Для HTTPS обычно создаёт туннель методом CONNECT. | Принимает запросы перед внутренним сервером. Может балансировать нагрузку, завершать TLS и передавать запрос дальше. |
| Слой | 7 · Прикладной | 7 · Прикладной |
| Транспорт | TCP | HTTP / HTTPS |
| Порты | 8080 (пример) | 80 / 443 |
| Пример | Корпоративный выход в веб через контролируемую точку. | Публичный вход к нескольким веб-приложениям. |
| На что смотреть | Обычный HTTPS CONNECT без перехвата TLS не раскрывает прокси содержимое защищённого запроса. | Если TLS завершается на прокси, участок до приложения требует отдельной оценки защиты. |

**Вывод:** сравнивайте протоколы по задаче, которую они решают. Иногда они дополняют друг друга, а не заменяют.
